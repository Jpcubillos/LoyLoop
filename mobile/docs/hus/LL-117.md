# LL-117: [MVP] Explorar comercios con búsqueda y filtros

## Descripción de la Historia
**Como cliente**, quiero un catálogo de comercios con búsqueda por nombre/categoría y filtros aplicables; resultados paginados, estados vacío y de error; distinguir membresía y disponibilidad; sin datos de otro tenant.

---

## Criterios de Aceptación y Reglas Verificables
1. **Búsqueda y Filtros**:
   - Búsqueda insensible a mayúsculas/minúsculas y acentos por nombre de comercio o categoría (`q` o `search`).
   - Filtro por categoría exacta (`category`).
   - Filtro por membresía (`membership=member` o `membership=all`).
   - Resultados ordenados de forma determinista (`name`, `id`) para evitar duplicados entre páginas.
2. **Paginación Estable**:
   - Paginación con `page` y `page_size` / `pageSize`.
   - Metadatos en respuesta: `page`, `pageSize`, `total`, `totalPages`, `hasNext`, `hasPrev`.
3. **Exclusión de Comercios Inactivos**:
   - Comercios con suscripción o estado suspendido, cancelado o inactivo (`BusinessPlanAssignment.status in ['suspended', 'cancelled', 'inactive']`) no aparecen en el catálogo.
   - Acceso directo por slug a un comercio inactivo responde `404 Not Found`.
4. **Distinción de Membresía y Disponibilidad**:
   - Cada comercio reporta si el cliente autenticado es miembro (`is_member`), sus puntos locales acumulados (`points_balance`, permanentes y no gastables) y su nivel (`tier`).
   - Se reporta la disponibilidad y dirección/sucursal del comercio.
5. **Aislamiento Multi-Tenant**:
   - La identidad del cliente se resuelve exclusivamente mediante el JWT autenticado del servidor.
   - Ningún parámetro enviado por el cliente puede seleccionar el progreso de otro usuario o tenant.
6. **Manejo de Estados en Frontend**:
   - Estado de carga (skeletons / shimmers).
   - Estado de error de red con opción y botón de reintento.
   - Estados vacíos diferenciados:
     - Búsqueda/filtro sin coincidencias: *"No encontramos coincidencias para tu búsqueda. Prueba con otro nombre o categoría."*
     - Pestaña de membresías vacía: *"Aún no eres miembro de ningún comercio. Explora y únete para acumular puntos permanentes."*
     - Catálogo general vacío: *"No hay comercios disponibles en este momento."*

## Implementación Técnica

### 1. Backend (Django REST Framework)
- `backend/loyalty/discovery_api.py`:
  - Enriquecimiento de `DiscoveryView.get`:
    - Exclusión automática de comercios inactivos (`BusinessPlanAssignment.objects.filter(status__in=['suspended', 'cancelled', 'inactive'])`).
    - Filtro `Q(name__icontains=q) | Q(category__icontains=q) | Q(description__icontains=q)`.
    - Filtro de categoría (`category__iexact=category`).
    - Filtro y marcación de membresías (`BusinessMembership.objects.filter(customer=customer)`).
    - Paginación determinista con ordenamiento `order_by('name', 'id')`.
    - Metadatos de paginación (`pagination: { page, pageSize, total, totalPages, hasNext, hasPrev }`).
- `backend/loyalty/customer_api.py` / `discovery_api.py`: Acceso a slugs inactivos retorna 404.

### 2. Frontend Web (Next.js)
- `app/c/comercios/page.tsx`:
  - Componente cliente interactivo con datos reales de la API `/api/backend/discovery/`.
  - Pestañas *"Explorar todos"* vs *"Mis comercios"*.
  - Buscador en tiempo real con debounce y botón para limpiar.
  - Chips de categorías dinámicas.
  - Tarjetas de comercios con badges de puntos acumulados, nivel local y disponibilidad.
  - Controles de paginación (anterior, siguiente, indicador de página y total).
  - Estados accesibles de carga, vacío y error con botón *"Reintentar"*.
- `lib/data/customer.ts`:
  - `getExploreCatalog()`: cliente tipado con soporte para búsqueda, filtros de categoría/membresía y paginación.
- `app/api/backend/[...path]/route.ts`:
  - Proxy actualizado para propagar query strings de forma segura (`?q=...&category=...`).
- `lib/backend/server.ts`:
  - Validación de ruta segura que admite parámetros de consulta query string (`(?:\?[a-zA-Z0-9_=&%-]*)?`).

### 3. Mobile App (Expo / React Native)
- `mobile/src/lib/business-api-client.ts`:
  - Soporte para parámetros de consulta en `createBusinessApi` manteniendo la validación estricta de rutas y URLs.
- `mobile/src/lib/loyloop-data.ts`:
  - `getBusinesses()` admite parámetros opcionales de búsqueda, categoría, membresía y paginación.
  - Agregado campo `isAvailable` en `BusinessSummary`.
- `mobile/src/app/comercios.tsx`:
  - Paginación con controles Anterior/Siguiente y conteo de páginas.
  - Reseteo de página a 1 ante cambios en filtros, pestañas o búsqueda.
  - Estados vacíos contextualizados según el filtro o pestaña activa.
  - Distinción de membresía y disponibilidad.
