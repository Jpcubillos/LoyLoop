# LL-11 Implementation Plan

**Goal:** Registro, acceso, cierre y recuperación de clientes con identidad estable y errores seguros.

**Architecture:** Supabase Auth existente, vínculo privado a perfil mediante RPC y flujos por OTP en la misma UI. Reutilizar primitivas LoyLoop.

**Tech Stack:** Expo SDK 57, React Native, TypeScript, Supabase, SecureStore.

**Spec:** `docs/hus/LL-11.md`, Jira LL-11, LL-39 y LL-40.

## Tareas

- [x] LL-39: migración `customer_identities` y RPC propia, con prueba SQL aislada de permisos/idempotencia.
- [x] LL-39: servicios de identidad, normalización/validación, errores seguros y flujos Auth con pruebas de cliente simulado.
- [x] LL-39: almacenamiento nativo seguro, limpieza de sesión, renovación en primer plano y recarga de datos al cambiar sesión.
- [x] LL-40: adaptar login con alta, confirmación y recuperación por OTP; mantener estilo y accesibilidad.
- [x] Verificar TypeScript, pruebas unitarias/SQL, recorrido web y bundles Android/iOS/web; documentar requisitos remotos y evidencia por criterio.

## Revisar especialmente

Alta duplicada sin sesión, código vencido, cambios simultáneos de sesión, error al guardar contraseña tras OTP, sesiones grandes y migración desde AsyncStorage, perfil histórico sin duplicar saldos. Ninguna prueba debe enviar correos o aprobar reclamos reales.
